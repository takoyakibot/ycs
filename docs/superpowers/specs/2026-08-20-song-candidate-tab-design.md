# 選択したタイムスタンプから楽曲マスタの候補を提示するタブ

## 概要

タイムスタンプ正規化画面に「候補」タブを追加する。タイムスタンプを1件選ぶと、そのテキストから楽曲マスタの候補を自動で検索して並べる。元テキストを区切り文字で分割したチップを押し引きすることで、検索条件を人が調整できる。

## 背景・目的

タイムスタンプを楽曲マスタに紐づける作業は、現在「楽曲マスタ」タブで曲名を手入力して検索する必要がある。1件ずつ入力するのは手間が大きい。

一方、自動紐付け（`AutoLinkService`）を精度改善で解決しようとすると、どこまで行っても誤紐付けのリスクが残る。Issue #675 のとおり自動紐付けの結果はレビューを経ずに公開されるため、誤りがそのまま公開情報になる。照合方式を変えても（PR #649）、Issue #672 のように「マスタの曲名がより長い実在の曲名の一部になっている」ケースで誤る。

しかし人が見れば、ごちゃごちゃした文字列の中でもどこが曲名かはすぐ分かる。**判断は人がして、探す手間だけを機械に任せる**のが現実的である。本機能はそのための導線を作る。

## スコープ

### 対象

- 正規化画面への「候補」タブの追加
- タイムスタンプを1件選んだときの候補の自動検索
- 元テキストを分割したチップによる絞り込み
- 候補タブを開いている間、タイムスタンプの選択を単一選択にする

### 対象外

- 自動紐付けの改善（本機能は自動紐付けを置き換える方向の施策であり、`AutoLinkService` 自体には手を入れない）
- PR #649 の照合方式・照合辞書の取り込み（全楽曲マスタをメモリにキャッシュする設計で、Issue #673 のとおり本番で500になる。1件ずつ候補を出す用途には重すぎる）
- 複数タイムスタンプに対する一括の候補提示（どのテキストのチップを出すか決まらない。一括紐付けは従来どおり「楽曲マスタ」タブで行う）
- 候補の並び順のスコアリング（まずは検索結果の既定順で出す）

## 前提: あいまい検索の取り込み

本機能の「初回の候補検索」は、元テキストを区切りで分割し、ノイズ（cover / MV など）を除いた語で AND 検索する処理である。これは未マージのブランチ `claude/timestamp-search-delimiter-noise-w8i3pt`（`QueryHelper::splitFuzzyKeywords()` / `applyFuzzySearch()`）が既に持っている。

そのため本機能は、このブランチを先に取り込むことを前提とする。取り込みにあたり次を直す必要がある。

- **複合語のノイズが除去されない（Critical）**: `IGNORE_KEYWORDS` の `music video` はスペースを含む複合語だが、`splitFuzzyKeywords()` はテキストを単語単位に分割した後で完全一致比較している。そのため `music` がどのエントリとも一致せず検索語として残り、`夜に駆ける / YOASOBI (Music Video)` の検索が0件になる。無視ワード側も同じトークン化で展開してから比較する
- **先頭の数値トークン除去が1個までしか効かない（Important）**: `00:12:34 ロキ / みきとP` のような貼り付けで `12` と `34` が検索語として残り0件になる。連続する先頭の数値トークンをまとめて除去する
- `resources/js/songs/normalize.js` の競合2箇所（コンストラクタのプロパティ追加、メソッドの隣接）を解決する

取り込んだ時点で「検索欄にタイムスタンプの文言を貼れば候補が探せる」状態になるため、本機能が途中で止まっても価値が残る。

## 設計

### 1. タブの追加

`resources/views/songs/index.blade.php` の既存タブ（Spotify検索 / 手動登録 / 楽曲マスタ）に「候補」を追加する。既存タブと同じ `tab-button` / `tab-content` の構造に従う。

### 2. 候補の検索とチップの取得

タイムスタンプを1件選んだ時点で、専用のエンドポイントを1本叩く。チップの分割と初回の候補検索をまとめて返す。

```
GET /api/songs/candidates?text=<元テキスト>
→ {
    "parts": ["今日から思い出", "Aimer", "cover"],
    "ignored": ["cover"],
    "songs": [ ...候補... ],
    "total": 2
  }
```

- `parts`: 元テキストを `TextNormalizer::splitBySeparators()` で分割した結果。チップとして表示する
- `ignored`: `TextNormalizer::isIgnorablePart()` が無視対象と判定したパーツ。チップの初期状態で未選択にする
- `songs` / `total`: `ignored` を除いたパーツで AND 検索した候補

分割の判定を JS 側に持たせるとサーバー側の正規化ロジックと二重管理になるため、分割はサーバーで行う。

フックは `toggleTimestampSelection()`。ここには既に「1件選択時に Spotify 検索欄へテキストを入れる」処理があるので、同じ場所に足す。候補タブが開かれていないときは叩かない（無駄なリクエストを避ける）。

### 3. チップ操作後の再検索

チップを押し引きしたら、**選択されているチップの文字列をスペースで連結して既存の `/api/songs` にあいまい検索モードで投げる**。パーツの分割結果は変わらないので、`/api/songs/candidates` を叩き直す必要はない。

初回の候補も「`ignored` を除いたパーツで検索した結果」なので、初回とチップ操作後で検索条件の作り方は同じである（チップの選択状態がそのまま検索語になる）。経路を1つに保つため、初回のレスポンスもこの規則で計算した結果を返す。

- **チップが全て外れている場合**: 検索しない（全件が出ても候補として意味がない）。「チップを選んでください」と表示する
- **0件の場合**: 「チップを外して条件を緩めてください」と案内する

### 4. タイムスタンプの単一選択（ラジオボタン）

候補タブを開いている間は、タイムスタンプの選択を単一選択にする。

- `createTimestampElement()` の input を `type="radio"`（同一 name）で描画する
- 別の行を選ぶと前の選択が外れる。同じ行を選び直すと解除できる（誤選択を戻せるようにする）
- 候補タブを開いた時点で複数選択されていた場合は、最後に選択した1件（`selectedTimestamps` の末尾）だけを残す
- 「全選択」ボタンは候補タブでは無効にする（単一選択と矛盾するため）。「全解除」は有効のまま
- 他のタブへ切り替えると複数選択に戻る。選択済みの1件はそのまま維持する

### 5. 候補の選択と紐付け

候補をクリックすると既存の `selectedSong` に入る。以降は既存の紐付けフロー（`linkSongBtn` → `linkTimestamps()`）をそのまま使う。紐付け処理には手を入れない。

## テスト

### 自動テスト（PHP）

- `QueryHelper` の修正: 複合語のノイズ（`(Music Video)`）が除去されること、連続する先頭数値トークンが除去されること、それぞれで候補が返ること
- `/api/songs/candidates`: 区切りで分割されること、無視対象のパーツが `ignored` に入ること、`ignored` を除いたパーツで検索した候補が返ること、空文字・記号のみの入力で壊れないこと、未認証で弾かれること

### 手動確認

チップ操作とタブ切り替えは JavaScript のため自動テストの基盤がない（Issue #665）。Playwright で実際に操作して次を確認する。

- タイムスタンプを選ぶと候補が出ること
- チップを押し引きすると候補が変わること
- チップを全て外すと案内が出ること
- 候補タブでタイムスタンプがラジオボタンとして振る舞うこと（別の行を選ぶと前が外れる）
- 候補タブを開いたときに複数選択が1件に絞られること
- 他タブに戻ると複数選択に戻ること
- 候補を選んで紐付けができること
- ダークモードとスマホ幅で崩れないこと
