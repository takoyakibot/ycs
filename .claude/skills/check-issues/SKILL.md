# Issue一覧確認・修正コマンド

オープンなIssue全体を確認し、修正可能なものをワークフローに従って対応してください。

## オプション

- `--auto`: 自律モード。ユーザーへの確認を省略し、Issue選択からマージまで自動で実行する

## 動作モード判定

`$ARGUMENTS` に `--auto` が含まれている場合は**自律モード**で動作する。

### 通常モード（デフォルト）
- Issue選択時にユーザーに確認
- PR作成後にユーザーに変更内容を確認させる
- マージ前にユーザーの承認を得る

### 自律モード（--auto）
- 最も対応しやすいIssue（バグ修正優先、難易度低い順）を自動選択
- PR作成後の確認を省略
- レビューで問題がなければ自動マージ
- 完了後、次のIssueがあれば続けて対応

## 手順

1. **Issue一覧の確認**
   - `gh issue list --state open` でオープンなIssueを一覧表示
   - **全Issueの本文を `gh issue view <番号>` で読む**（タイトルだけで判断しない）
   - 各Issueについて以下を評価し、対応可否を判定する:
     - 対応方針が明確か（具体的な修正案や手順が記載されているか）
     - 設計判断や未決事項があるか（「検討事項」「未決事項」「対応案」の選択肢が複数あるか）
     - 他のIssueへの依存があるか
     - ブラウザ検証が必須か（UI変更でサーバーサイドテストだけでは確認できないもの）
   - 【通常モード】修正可能なIssueをユーザーに提示し、どれを対応するか確認
   - 【自律モード】最も対応しやすいIssueを自動選択（バグ修正 > 機能追加、難易度低 > 高）。部分対応が可能なIssue（サブ課題の一部だけ対応可能など）も候補に含める

2. **対応するIssueが決まったら、ワークフローに従って対応**
   - developの最新化
   - 適切なブランチ名で新しいブランチを作成
   - 修正を実施
   - 変更内容をレビュー
   - 問題があれば修正
   - PRを作成（Issueを自動クローズするため `Closes #番号` を含める）
   - PRをレビュー
   - 指摘事項があれば修正
   - 【通常モード】ユーザーに変更内容を確認させる
   - 【自律モード】レビューで問題がなければ続行
   - 問題がなければマージ

3. **複数のIssueがある場合**
   - 【通常モード】優先度や難易度を考慮してユーザーに提案、一度に1つのIssueを対応
   - 【自律モード】マージ完了後、次のIssueに自動で移る（対応可能なIssueがなくなるまで継続）

4. **留意点**
   - ソースの修正を伴う作業は常にワークフローに従う
   - 基本的にdevelopには直接コミットしない
   - レビューで発見された問題がブランチの範囲外の場合は、別Issueを追加して対応
