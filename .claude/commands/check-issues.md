# Issue一覧確認・修正コマンド

オープンなIssue全体を確認し、修正可能なものをワークフローに従って対応してください。

## 手順

1. **Issue一覧の確認**
   - `gh issue list --state open` でオープンなIssueを一覧表示
   - 各Issueの内容を確認し、修正可能かどうかを判断
   - 修正可能なIssueをユーザーに提示し、どれを対応するか確認

2. **対応するIssueが決まったら、ワークフローに従って対応**
   - developの最新化
   - 適切なブランチ名で新しいブランチを作成
   - 修正を実施
   - 変更内容をレビュー
   - 問題があれば修正
   - PRを作成（Issueを自動クローズするため `Closes #番号` を含める）
   - PRをレビュー
   - 指摘事項があれば修正
   - ユーザーに変更内容を確認させる
   - 問題がなければマージ

3. **複数のIssueがある場合**
   - 優先度や難易度を考慮してユーザーに提案
   - 一度に1つのIssueを対応し、完了後に次のIssueに移る

4. **留意点**
   - ソースの修正を伴う作業は常にワークフローに従う
   - 基本的にdevelopには直接コミットしない
   - レビューで発見された問題がブランチの範囲外の場合は、別Issueを追加して対応
