# Issue修正コマンド

指定されたIssueを確認し、修正可能な内容をワークフローに従って修正してください。

## 引数
- `$ARGUMENTS`: Issue番号またはIssue URL

## 手順

1. **Issueの確認**
   - `gh issue view $ARGUMENTS` でIssueの内容を確認
   - 修正可能かどうかを判断

2. **ワークフローに従って対応**
   - developの最新化
   - 適切なブランチ名で新しいブランチを作成
   - 修正を実施
   - 変更内容をレビュー
   - 問題があれば修正
   - PRを作成（Issueを自動クローズするため `Closes #番号` を含める）
   - PRをレビュー
   - 指摘事項があれば修正
   - ユーザーに変更内容を確認させる
   - 問題がなければマージ

3. **留意点**
   - ソースの修正を伴う作業は常にワークフローに従う
   - 基本的にdevelopには直接コミットしない
   - レビューで発見された問題がブランチの範囲外の場合は、別Issueを追加して対応
